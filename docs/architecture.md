# Архитектура myRPC

## Общая схема

```text
+----------------+          socket          +----------------+
| myRPC-client   | -----------------------> | myRPC-server   |
+----------------+                          +----------------+
| host           |                          | /etc/myRPC     |
| port           |                          | whitelist      |
| command        |                          | syslog/logfile |
+----------------+                          +----------------+
                                                    |
                                                    v
                                           +----------------+
                                           | worker process |
                                           +----------------+
                                                    |
                                                    v
                                           +----------------+
                                           | bash command   |
                                           +----------------+
```

## Клиент

Клиент получает аргументы командной строки.
Затем он определяет имя текущего пользователя.
После этого формирует запрос.

Формат запроса:

```text
login:command
```

Далее клиент отправляет запрос серверу.
Ответ сервера выводится в терминал.

## Сервер

Сервер читает конфигурацию:

```text
/etc/myRPC/myRPC.conf
```

Также сервер читает whitelist:

```text
/etc/myRPC/users.conf
```

После запуска сервер открывает socket.
Для TCP stream каждое подключение обрабатывается в отдельном процессе.

## Проверка пользователя

Сервер получает имя пользователя из запроса.
Затем он ищет это имя в `users.conf`.

Если пользователь найден, команда выполняется.
Если пользователя нет, сервер возвращает ошибку.

## Выполнение команды

Команда выполняется через `/bin/bash -c`.

Вывод stdout пишется во временный файл.
Вывод stderr пишется во временный файл.

Шаблоны файлов:

```text
/tmp/myRPC_stdout_XXXXXX
/tmp/myRPC_stderr_XXXXXX
```

После выполнения сервер читает нужный файл.
Результат отправляется клиенту.

## Сигналы

Сервер обрабатывает сигналы:

```text
SIGINT   корректное завершение
SIGTERM  корректное завершение
SIGHUP   перечитать whitelist
SIGCHLD  убрать завершённые дочерние процессы
```
